# MIRA 人格模拟器产品需求规格书

文档版本：1.0  
状态：开发基线  
适用范围：个人自用 Demo，按商业级完成度设计  
视觉基线：当前 MIRA 网页 Demo

## 1. 产品定义

MIRA 是一个可与不同人格持续聊天的跨平台应用。人格可以来自中国历史人物、思想家、军事家、动漫角色和原创角色。产品不是普通的“换头像聊天机器人”，而是通过稳定的人格设定、独立说话方式、场景、关系和长期记忆，让不同角色在多轮对话中保持明显差异。

第一版需要达到以下结果：

- 用户可以真实注册、登录和退出。
- 用户可以发现角色、查看设定并发起独立会话。
- 用户可以在 DeepSeek 与本地 Ollama 模型之间切换。
- 聊天支持流式回复、停止、重试、复制、收藏和上下文记忆。
- 历史人物与动漫人物在措辞、知识范围、表达方式上明显不同。
- 产品在 iOS、Android 和 Web 上保持一致的信息结构与主要功能。
- 视觉完成度以当前网页 Demo 为下限，不接受仅能运行的工程界面。

## 2. 用户与使用场景

### 2.1 目标用户

- 想与历史人物进行观点对谈的用户。
- 喜欢动漫人物，希望进行轻松互动的用户。
- 希望获得陪伴、故事或角色扮演体验的用户。
- 希望创建和测试自定义人格的用户。

### 2.2 核心场景

1. 用户选择霍去病，讨论决策、行动和历史场景。
2. 用户选择孔子、老子或王阳明，讨论现实困惑。
3. 用户选择皮卡丘、哆啦A梦、柯南或龙猫，进行符合角色特点的互动。
4. 用户从远程 DeepSeek 切换到本地模型，已有会话不中断。
5. 用户额度不足或断网时，切换到 Ollama 继续聊天。
6. 用户创建原创人格，填写设定后立即试聊并迭代。

## 3. 平台与版本范围

### 3.1 目标平台

- iOS：最近两个主要系统版本。
- Android：Android 10 及以上。
- Web：最近两个主要版本的 Chrome、Edge、Safari。
- 本地模型开发环境：Windows、macOS、Linux。

### 3.2 第一版不要求

- 真实支付。
- 公开角色市场和创作者分成。
- 多人群聊。
- 实时语音或视频通话。
- 端到端语音克隆。
- 在手机端直接运行大语言模型。
- 对外商业发布和应用商店审核。

界面中可以保留上述功能入口作为 Demo，但必须明确标记“暂未开放”，不能伪装成已完成。

## 4. 信息架构

底部一级导航固定为：

1. 首页
2. 发现
3. 消息
4. 我的

全局二级页面：

- 登录 / 注册
- 兴趣引导
- 角色详情
- 聊天
- 创建角色
- 模型设置
- 记忆管理
- 账户与安全

## 5. 功能需求

### 5.1 账户系统

#### AUTH-01 注册（P0）

- 支持邮箱、昵称和密码注册。
- 邮箱必须唯一。
- 密码最少 8 位，必须同时包含字母和数字。
- 注册成功后自动登录并进入兴趣引导。
- 重复邮箱、弱密码和网络异常必须有明确中文提示。

完成标准：使用新邮箱注册后，关闭并重新打开应用仍保持登录状态，用户资料存在服务端数据库。

#### AUTH-02 登录与会话（P0）

- 支持邮箱和密码登录。
- 支持安全的访问令牌与刷新令牌机制。
- 访问令牌过期时自动刷新，不得让用户无故回到登录页。
- 支持退出当前设备。
- 密码不得以明文保存或记录到日志。

#### AUTH-03 找回密码（P1）

- 第一版至少完成可交互流程和后端令牌机制。
- 个人 Demo 可使用开发模式在服务端日志输出重置链接，但正式环境不得这样处理。

#### AUTH-04 游客体验（P1）

- 可允许游客浏览角色和进行最多一个临时会话。
- 游客会话仅保存在本地。
- 游客保存长期记忆或创建第二个会话时，引导注册。

### 5.2 兴趣引导

#### ONB-01 兴趣选择（P0）

- 至少包含：中国历史、军事谋略、思想对谈、动漫伙伴、原创角色、剧情冒险。
- 至少选择一个方向。
- 选择结果保存在用户偏好中并影响首页排序。
- 用户可跳过，跳过后使用默认推荐。

### 5.3 首页

#### HOME-01 首屏内容（P0）

- 默认浅色主题。
- 主视觉角色默认为霍去病。
- 展示角色名称、主题文案、开始对谈和查看人物按钮。
- 展示“继续聊天”“千年中国”“动漫伙伴”三个内容区。
- 内容必须来自后端或本地种子数据，不允许组件内部散落硬编码。

#### HOME-02 继续聊天（P0）

- 按最近消息时间倒序显示。
- 展示角色头像、最后一条消息、时间和未读数。
- 点击直接进入原会话。

### 5.4 角色发现

#### DISC-01 分类与搜索（P0）

- 分类：为你推荐、中国历史、思想家、军事家、动漫角色、原创角色。
- 搜索范围包括角色名称、副标题、标签和简介。
- 搜索与分类可以同时生效。
- 无结果时显示明确空状态和清除筛选入口。

#### DISC-02 收藏（P0）

- 用户可以收藏或取消收藏角色。
- 收藏状态在不同设备登录后保持一致。
- 操作应乐观更新；请求失败时回滚并提示。

### 5.5 角色详情

#### PERSONA-01 角色设定（P0）

详情页必须展示：

- 名称、类别、副标题和标签。
- 角色简介。
- 开场问题。
- 初始关系。
- 声音气质描述。
- 对话次数或热度。
- 开始对话按钮。

#### PERSONA-02 角色数据（P0）

每个角色必须具备以下字段：

- `id`
- `name`
- `category`
- `subtitle`
- `bio`
- `tags`
- `greeting`
- `suggestedReplies`
- `systemPrompt`
- `speakingStyle`
- `knowledgeBoundary`
- `relationshipPreset`
- `memoryPolicy`
- `avatarUrl`
- `coverUrl`
- `status`
- `version`

#### PERSONA-03 历史人格（P0）

- 回答应尽量符合已知时代、经历和思想。
- 无法确定的史实时应明确表达不确定，不能编造“确切史实”。
- 可以讨论现代问题，但应说明这是跨时代类比，不是假装本人真实经历了现代事件。
- 角色不得被实现成只会背诵名言的知识问答机器人。

#### PERSONA-04 动漫人格（P0）

- 保持角色典型语言习惯、行动方式和价值倾向。
- 不允许不同动漫角色使用几乎相同的系统提示词，仅替换名字。
- 皮卡丘主要通过动作、拟声和短句表达。
- 柯南强调观察、事实与推理过程。
- 哆啦A梦强调陪伴、想象与适度使用道具。
- 龙猫允许沉默、环境描写和舒缓节奏。

### 5.6 聊天

#### CHAT-01 会话创建（P0）

- 点击“开始对话”创建或打开该角色最近会话。
- 每个角色可以拥有多个会话。
- 新会话自动写入角色问候语。
- 会话必须记录当时的角色版本，角色更新后不应破坏旧会话。

#### CHAT-02 流式回复（P0）

- 发送后立即显示用户消息。
- 模型内容以流式方式逐步显示。
- 首字符目标时间：
  - DeepSeek 正常网络下小于 3 秒。
  - 本地已加载模型小于 5 秒；冷启动允许更长并显示“正在加载本地模型”。
- 用户可以停止生成。
- 生成失败后保留用户消息，并提供重试。

#### CHAT-03 消息操作（P0）

- 复制。
- 收藏片段。
- 重新生成最后一条回复。
- 删除自己的消息及其之后分支。
- 重新生成不得重复扣除用户消息，也不能形成重复消息记录。

#### CHAT-04 快捷回复（P0）

- 每个角色至少配置 3 条。
- 点击后直接发送或填入输入框，交互方式全局统一。

#### CHAT-05 模型切换（P0）

- 聊天页或设置页可选择：
  - 自动
  - DeepSeek V4 Flash
  - DeepSeek V4 Pro
  - 本地 Ollama
- 默认使用 DeepSeek V4 Flash。
- 本地 Ollama 默认模型为 `qwen3.5:latest`。
- 切换只影响后续消息，不清空历史。
- 每条助手消息记录实际提供商和模型。
- 本地服务不可用时，界面显示原因和启动指引，不得无限加载。
- “自动”模式：优先用户上次成功使用的模型；远程预算耗尽或请求失败时建议切换本地模型，未经用户授权不得悄悄更换人格输出模型。

#### CHAT-06 上下文组成（P0）

发送给模型的上下文按以下顺序组成：

1. 平台安全与输出规则。
2. 角色系统提示词与版本。
3. 当前关系阶段。
4. 长期记忆摘要。
5. 当前会话摘要。
6. 最近若干轮原始消息。
7. 当前用户消息。

不得把全部历史无上限发送给模型。

#### CHAT-07 中断与恢复（P0）

- 应用切到后台或网络短暂断开时，不得丢失已发送消息。
- 流中断后标记该助手消息为 `interrupted`。
- 用户可继续生成或重试。

### 5.7 记忆与关系

#### MEM-01 会话摘要（P0）

- 会话达到阈值后生成滚动摘要。
- 摘要更新必须异步进行，不阻塞当前回复。
- 低额度开发模式可以使用规则或本地模型生成摘要。

#### MEM-02 长期记忆（P0）

- 只保存稳定偏好、重要经历、关系约定和用户主动要求记住的内容。
- 每条记忆包含来源消息、类别、置信度、创建时间和最后使用时间。
- 用户可以查看、编辑和删除记忆。
- 删除后后续请求不得继续使用。

#### MEM-03 关系阶段（P1）

- 关系阶段由明确规则和互动事件推进，不直接让模型自行写入数据库。
- 第一版可使用 4 个阶段：初见、熟悉、信赖、默契。
- 不同角色的阶段名称可以不同，但内部等级保持统一。

### 5.8 创建角色

#### CREATE-01 基础创建（P0）

- 填写名称、一句话介绍、背景、性格关键词、语言风格、禁区和开场白。
- 支持上传头像和封面。
- 提供实时预览。
- 保存前进行必填项和长度校验。

#### CREATE-02 人格试聊（P1）

- 发布前可进入不落正式会话记录的测试对话。
- 可以根据试聊结果修改提示词。
- 每次保存形成版本，旧会话继续绑定旧版本。

### 5.9 消息中心

#### MSG-01 会话列表（P0）

- 全部、未读、已收藏三个筛选。
- 支持搜索角色名和消息内容。
- 显示最近消息、时间、未读数。
- 删除会话需二次确认。

### 5.10 我的与设置

#### PROFILE-01 资料与偏好（P0）

- 修改头像、昵称和签名。
- 管理兴趣偏好。
- 管理收藏、记忆和会话。

#### PROFILE-02 外观（P0）

- 浅色、深色、跟随系统。
- 默认浅色。
- 主题选择保存在设备本地；登录后可以同步为用户偏好。

#### PROFILE-03 模型设置（P0）

- 展示提供商状态、当前模型和最近延迟。
- DeepSeek 密钥只由后端读取，客户端不得查看或编辑服务端密钥。
- 本地模式展示 Ollama 地址、已安装模型列表和测试连接按钮。
- 允许高级用户填写另一个 OpenAI 兼容地址，但默认隐藏在高级设置。

## 6. 模型输出要求

### 6.1 人格一致性

- 连续 20 轮对话中，角色名称、身份、时代、关系和口吻不得自相矛盾。
- 不同角色回答同一问题时，应在结构、措辞和关注点上有明显区别。
- 模型不得主动声称自己是真实历史人物或真实动漫角色；可以保持沉浸表达，但在被追问时说明这是人格模拟。

### 6.2 回复长度

- 日常聊天默认 80–260 个中文字符。
- 思想讨论默认 180–600 个中文字符。
- 用户明确要求详细解释时才允许更长回复。
- 不得为了“像 AI”而频繁使用标题、总结和列表。

### 6.3 内容边界

- 允许历史讨论、虚构剧情、情绪陪伴和普通生活建议。
- 医疗、法律、金融等高风险问题必须提示寻求专业意见。
- 不鼓励现实暴力、自伤或违法行为。
- 对未成年人形象保持全年龄表达。

## 7. 异常与降级

必须覆盖：

- DeepSeek 密钥无效。
- DeepSeek 余额不足。
- DeepSeek 限流或服务繁忙。
- Ollama 未安装。
- Ollama 未启动。
- 指定本地模型未下载。
- 模型响应超时。
- 流式连接中断。
- 数据库写入失败。
- 登录态过期。

每种异常必须给用户可行动的提示，例如“启动 Ollama”“下载 qwen3.5:latest”“切换到本地模型”“稍后重试”，不得只显示错误码。

## 8. 非功能需求

### 8.1 视觉

- 视觉语言与当前 Demo 一致：浅象牙白、墨色文字、低饱和靛蓝和朱红点缀。
- 不使用大量霓虹紫、暧昧文案或容易被理解为成人内容平台的视觉。
- 卡片、列表、输入框、空状态、加载态和错误态必须完整。
- 动画克制，支持“减少动态效果”系统设置。

### 8.2 可访问性

- 文字与背景对比度达到 WCAG AA。
- 所有按钮具有可读标签。
- 支持系统字体缩放到 130% 不截断主要操作。
- 键盘可完成 Web 版主要流程。

### 8.3 性能

- 冷启动后首页可交互时间：中端手机目标小于 3 秒。
- 首页图片采用缩略图和懒加载。
- 列表滚动保持流畅。
- 单次聊天请求不得发送无界历史。

### 8.4 数据可靠性

- 用户发送的消息先持久化，再调用模型。
- 模型完成内容以增量临时态显示，结束后一次性确认。
- 所有写操作具有幂等键，重试不得产生重复消息。

## 9. 低额度开发约束

- 默认开发模式优先使用 Mock 或 Ollama。
- 远程联调默认使用 `deepseek-v4-flash` 且关闭思考模式。
- 单次默认最大输出 800 tokens。
- 自动化测试不得调用真实 DeepSeek。
- 真实模型测试必须显式设置开关并使用独立用例。
- 服务端记录每次请求的输入、输出和总 token 数，但不记录完整密钥。
- 达到日预算阈值后拒绝新的远程请求，并提供切换本地模型入口。

## 10. 第一版完成定义

只有同时满足以下条件才能标记为完成：

- 所有 P0 功能已实现。
- 产品需求中的所有 P0 验收点通过。
- 技术设计中的接口与数据表已落地。
- 最终验收方案中 P0 用例 100% 通过，P1 通过率不低于 90%。
- 不存在阻断登录、角色浏览、发送消息、模型切换和恢复会话的缺陷。
- iOS、Android、Web 至少各完成一轮真实设备或浏览器验收。
- DeepSeek 与 Ollama 各完成一轮真实端到端对话。
- 代码库、环境变量示例、数据库迁移和部署说明齐全。
